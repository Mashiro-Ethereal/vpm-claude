## 0. 被查的想法

- **构建时**（Stage1、Stage2）：各任务的谓词由 agent 独立编写，任务之间不共用代码。只有三点要求：
  - 谓词以对象为参数；
  - 只通过统一的世界视图读取状态；
  - 附一句自然语言说明。
- **Stage3 重标之前**加一步合并：
  - 先按说明和参数，找出可能同义的谓词；
  - 再把候选放到彼此任务保存的轨迹上运行（参数对应到对方任务的物体），判定几乎一致的，才合并为一个编号；
  - 合并看行为，不看名字。
- **使用方式：** 词表在训练视觉 VPM 之前冻结，以查询方式使用。输入图像、任务描述和一个实例（谓词编号加参数名或物体框），输出该实例是否成立。
- **词表外的谓词**有两种补法：
  - 用它的说明去查询；
  - 写成词表中已有谓词的组合，再用轨迹验证。
- **与 tokenization 的类比**（你觉得有意思）：
  - 相同：词表从数据中归纳，训练前冻结，粒度需要取舍；
  - 不同：这里按判定一致做语义合并；合并有损；有词表外的问题。

## 2. 结论

- 【事实】这个想法的各个组成部分都有成熟先例：
  - 按外延判断同义：知识库与本体对齐；
  - 按执行输出判断等价：程序合成、广义规划中的特征去重；
  - 从各任务的程序中事后归纳出共享的库：DreamCoder 一脉。
- 【事实，限于本次检索】没有找到下面这种做法：各任务独立编写、以对象为参数的可执行谓词，放到彼此任务的状态上交叉执行，判定一致的事后合并，得到共享的标签空间，再用来训练视觉模型。已有工作的跨任务共享有三种方式：
  - 在构建期维护：把已有的谓词表交给 LLM，或一个领域只有一个候选池；
  - 按语言共享：ARM-FM，以及按文本嵌入去重的概念瓶颈模型；
  - 按名字共享：CRAFT。
- 【推导】可以算支撑性的方法贡献，不宜作为主贡献。它能否成立，取决于对比实验（本文 §5）。
- 【推导】查到的做法中有几条可以直接借用（本文 §6）。最要紧的三条：
  - 把等价拆成两个方向的包含；
  - 防止两个谓词都几乎不成立造成的“空洞一致”；
  - 用能区分两者的状态来检验。

## 3. 最接近的工作与区别

### 3.1 知识库与本体对齐：看外延，不看名字

- 【事实】PARIS（PVLDB 2011）在两个知识库之间对齐关系。
  - Pr(r ⊆ r′) 正比于 r 的实例对中同时属于 r′ 的比例；两个方向都成立，就判为等价。
  - 实例对应和关系对齐交替估计。
- 【事实】RESOLVER（JAIR 2009）同时用字符串相似度和共享的参数对，判断两个关系名是否同义。关系同义的结果是精度 90%、召回 35%。
- 【事实】Isaac 等（ISWC 2007）比较了按共同实例匹配概念的多种统计量。结论是：简单的度量常常胜过复杂的统计量。
- 【推导】这几项与“合并看行为”的原则相同；PARIS 的实例对应，相当于“参数对应到对方任务的物体”。区别在证据：
  - 它们只能使用两边都记录了的事实，证据稀疏，所以 RESOLVER 的关系召回只有 35%；
  - VPM 的谓词能执行，可以在对方任务的任何保存状态上直接运行，证据可以按需补充。

### 3.2 按执行输出判断等价

- 【事实】广义规划的 D2L（Bonet 等，AAAI 2019；Francès 等，AAAI 2021）按复杂度枚举特征。某个特征在训练集全部状态上的外延，如果与先前生成的特征相同，就作为冗余删掉。这是观察等价直接用在谓词式特征上。
- 【事实】AlphaCode（§4.6）在模型生成的测试输入上运行候选程序，输出相同的归为一类。原文指出，无效的测试输入也有助于分组。
- 【事实】CodeT 同时看两件事：各样本是否通过生成的测试，以及样本之间的输出是否一致（dual execution agreement）。
- 【事实】LLM 生成 PDDL 的工作里也有类似做法：
  - Mahdavi 等（NeurIPS 2024）的 Exploration Walk 在两个方向上抽随机动作序列，分别检查生成的领域模型和真实环境能否执行；
  - Oswald 等（ICAPS 2024）用计划交叉验证判断两个领域是否等价，并说明抽样一致只是等价的必要条件，出现不一致才能判定不等价。
- 【推导】区别：这些工作都在同一个问题或同一个候选池内去重或打分，D2L 还只认完全一致。VPM 要在不同任务独立写出的谓词之间做近似合并，合并的结果还要当作标签。

### 3.3 从各任务的程序中事后归纳出库

- 【事实】DreamCoder、Stitch（POPL 2023）、babble（POPL 2023）、LILO（ICLR 2024）都从已解出的程序中抽取公共结构，目标是压缩整个程序集。
  - babble 在给定的等式理论下判断等价；
  - LILO 另外用 LLM 给抽象命名、写说明（AutoDoc）。
- 【事实】用 LLM 构建工具库的工作：
  - ReGAL（ICML 2024）按查询的嵌入把样例分批，由 LLM 重构出辅助函数，再执行验证结果不变；
  - CRAFT（ICLR 2024）去重时，把函数名和参数个数都相同的工具分为一组，再让 GPT-4 从组里选最通用的一个；
  - TroVE 按各候选解执行结果的一致程度选解，并定期删掉少用的函数。
- 【事实】Berlot-Attwell 等（NeurIPS 2024 MATH-AI workshop）检查了 LEGO-Prover 和 TroVE：库函数几乎没有被复用，性能提升主要来自自我修正和自洽。
- 【推导】区别：
  - 这一脉合并的是结构（公共子程序），目的是以后写程序时复用；VPM 合并的是整个谓词的语义，目的是让视觉模型共享标签。
  - CRAFT 按名字分组，正是 VPM 要避免的“同名即同义”。

### 3.4 各类别分别生成概念，再汇总成全局词表（流程最像）

- 【事实】Label-free CBM（ICLR 2023）让 GPT-3 为每个类别列出概念，汇总后过滤：
  - 与已有概念的文本嵌入余弦相似度超过 0.9 的删去；
  - 与类别名相似度超过 0.85 的删去；
  - 在 CLIP 上激活不高的删去。

  然后训练概念瓶颈层。
- 【事实】LaBo（CVPR 2023）为每个类别生成候选概念，再用次模函数按判别性和多样性挑选。
- 【推导】流程与 VPM 最像：分别生成、汇总、冻结、训练视觉模型。区别有三点：
  - 去重按文本；
  - 概念是整张图的属性，不带对象参数；
  - 概念没有可执行的定义，也不用特权状态。

### 3.5 机器人规划中的谓词发明（领域最近）

- 【事实】pix2pred（RA-L）：
  - 让 VLM 对每条示范提出原子，提升为带类型的谓词后，按名字和类型去掉重复；
  - 所有示范的提议汇成一个候选池，用规划目标爬山选出子集；
  - 谓词由 VLM 按原子文本判定，能泛化到新目标。
- 【事实】Silver 等（AAAI 2023）按代价从文法中枚举 200 个候选谓词，用同样的方法挑选。全文关键词检索没有找到按数据等价去重的步骤。
- 【事实】也有在构建期维护共享谓词表的：
  - InterPreT 识别新谓词时，把已有谓词的说明交给 LLM，谓词集合在交互中不断增长；
  - Guan 等（NeurIPS 2023）维护一张谓词表喂回给 LLM，让它复用已有谓词，并要求每个新谓词附一句自然语言说明。
- 【事实，据 pix2pred 和 VisualPredicator 的转述，未读原文】James 等（ICLR 2022）按选项效果是否相同，把物体并为同一类型。这是按行为合并，但合并的是物体，不是谓词。
- 【事实】2025–2026 年的 UniPred（T-RO）、ExoPredicator（ICLR 2026）和 Xiao 等（arXiv 2607.06501），全文关键词检索都没有找到跨任务合并谓词的步骤。
- 【推导】这一脉的共享发生在构建期：要么一个领域一个候选池，要么把已有谓词表交给 LLM。挑选的标准是规划效用，不是事后按行为合并。

### 3.6 ARM-FM

- 【事实，据项目保存的原文摘录 `references/notes/_sources/structure_armfm_web.txt`】基础模型为每个任务生成三样东西：奖励机、Python 标注函数，以及每个自动机状态的语言说明。
  - 策略以状态说明的嵌入为条件；跨任务共享和零样本泛化（同一领域内的新组合）都靠这个嵌入。
  - 原文还指出，把自动机状态当作孤立符号的做法，要复用策略就得仔细做状态映射。
- 【推导】转来的说法“由 LLM 生成标注函数并跨任务复用”要修正：ARM-FM 不复用标注函数，共享靠的是语言。这对应 VPM 的补法 1（用说明去查询）。
- 【推导】行为合并是“经特权状态验证的对齐”。取消类型化的共享库后，Stage1 记录 §3.4 说“谓词带类型并在任务间共享”这条区别已不成立；行为合并可以替补它。

## 4. 问题 2：按行为一致判断等价，用在谓词或奖励函数上过吗

- 【事实】用过，但都不是为了合并：
  - 谓词式特征：D2L 删除外延相同的特征；
  - LLM 生成的符号模型：Exploration Walk、计划交叉验证；
  - 奖励函数：EPIC、DARD 在一个覆盖分布上比较两个奖励函数，比较之前先消去势函数整形（项目笔记 gleave2021epic.md、wulfe2022dard.md）。
- 【推导】EPIC 这类度量刻意不区分只差一个 PBRS 项的奖励，而 progress 起作用的正是这一项，所以不能用来比较 progress。谓词是布尔量，直接比较判定结果即可。
- 【事实，限于本次检索】没有找到用它来合并各任务独立编写的谓词、形成共享标签空间的工作。

## 5. 能否算贡献

- 【推导】把“按行为合并”写成一个新算法站不住，审稿人可以直接举出 D2L、PARIS、AlphaCode。
- 【推导】可以作为支撑性的方法贡献。表述为：取消人工谓词库之后，用交叉执行把各任务自主编写的谓词对齐成共享词表。它解决的是任务自治与跨任务标签一致之间的矛盾。成立与否要靠实验：
  - 与三种替代做法比较：不合并（各任务编号独立）、按名字合并（CRAFT 式）、按说明的嵌入合并（Label-free CBM、ARM-FM 式）。比较两项：标签冲突率，以及 Stage3 在 LIBERO-10 新组合上的泛化。
  - 报告词表大小、以及合并引入的不一致率随阈值变化的曲线。
  - 复用统计要配消融，避免 Berlot-Attwell 等指出的问题。
- 【推导】如果行为合并与按说明嵌入合并的效果相近，它就只是工程处理。
- **决定（2026-10-19）：** 列为 §0.4 贡献 3 下的子项，并在 §6.2 加上述对比实验。贡献 3 是“覆盖策略实际行为的过程监督”，共享词表就是这份多任务监督的标签空间。其中泛化部分的检验依赖 Stage3。

## 6. 可以借用的具体做法

1. **把等价拆成两个方向的包含**（来自 PARIS）。
   - 在对方任务的状态上，分别估计 P(p_B | p_A) 和 P(p_A | p_B)，两个都高才合并。
   - 只有一个方向高时（例如两个阈值不同的 `near`），记为蕴含，不合并。这条关系可以留给补法 2 和一致性检查用。
2. **设支持度门槛（推导）。**
   - 多数谓词在多数状态上为假，一致率会虚高。两个谓词在某个任务上都几乎不成立时，一致率接近 100%，却什么也证明不了。
   - 只在双方都有足够正例和反例的数据上判定。度量用正例集合的 Jaccard 或 Cohen's κ，按任务分别计算后取最小值，不把各任务的数据混在一起算。
3. **用能区分两者的状态来检验**（AlphaCode 生成测试输入，Exploration Walk 双向抽样，Oswald 等关于必要条件的说明）。
   - 一致只相对于所用的状态成立。
   - 状态样本要包括 Stage2 的失败和训练早期 rollout，以及随机或扰动过的状态。
   - 还可以主动找反例：在阈值附近扰动物体位姿，找到一个稳定的、两者判定不同的状态，就把它们拆开。
4. **不必先按说明筛候选（推导）。**
   - CRAFT 按名字分组、ReGAL 按嵌入分批、LaRe 按提示嵌入删冗余、Label-free CBM 按文本余弦去重，都是候选太多、执行太贵时的省钱办法；LaRe 原文明说，嵌入相似度比执行快。
   - VPM 每个任务只有十来个谓词，参数个数相同的配对可以在保存的状态上全部批量运行。
   - 先按说明筛，会漏掉说明不同的同义谓词，与“看行为不看名字”相悖。
   - 说明只用作先验和命名。合并后的编号，可以像 LILO 的 AutoDoc 那样，由 LLM 根据各成员的定义写一句说明。
5. **定代表实现**（D2L 保留先生成、复杂度较低的那个）。合并后要定一件事：
   - 每个编号用一个代表实现，统一重标所有任务的数据：标签一致；
   - 或者各任务保留自己的实现，编号只把视觉头绑在一起：忠于各任务经 Stage2 调定的语义。

   【待定】留到 Stage3 再定（VPM_idea §9 第 16 项）。
6. **聚类方式（推导）。** 近似一致没有传递性：A≈B、B≈C 推不出 A≈C。用全连接（组内每一对都过阈值），或以代表实现为中心、每个成员都与它比对，不用传递闭包。
7. **阈值怎么定（推导）。**
   - 合并的损失就是标签噪声。阈值可以和 VPM_idea §6 计划的人工抽查标签错误率挂钩：合并引入的不一致率，不超过 teacher 本身可接受的错误率。
   - 本文 §5 说的阈值曲线，就是 tokenization 类比里的粒度取舍。
   - 如果担心合并有损，可以保留各任务的细编号，把合并编号放在上一层，两层都训练。这类似 BPE 词表里基础 token 与合并 token 并存。
8. **参数绑定（推导）。**
   - 去掉类型标签后，判断一个绑定是否合法的标准：在对方任务的状态上运行不报错，且判定不是常数。
   - 每个任务的物体很少，参数个数相同的单射绑定可以全部枚举。
9. **补法 2 的先例。** ReGAL 把程序改写成调用库函数的形式，再执行验证结果不变。把新谓词写成词表谓词的组合、再在轨迹上验证，是同一种做法。
10. **视觉侧查询的先例。** 查询接口本身不构成贡献，但下面的做法可以直接借用：
    - Migimatsu 与 Bohg（2022）把图像和按参数顺序排列的物体框一起输入，输出各谓词是否成立，解决了 in(A, B) 这类参数顺序的问题；
    - SORNet（CoRL 2021）用物体的小图作查询，能泛化到没见过的物体；
    - SuccessVQA 把成功检测写成视觉问答；
    - pix2pred 按原子文本去问 VLM。

## 7. 对 Stage1 的要求

- 现有三点要求（以对象为参数、只读世界视图、附一句说明）够用。再补两点：
  - 谓词体内不写死本任务的物体名或任务特有的读数，物体只经参数进入，否则无法在别的任务上运行。任务特有的几何（如孔的坐标系）要能由参数对象算出。
  - 合并放在 Stage2 之后，Stage2 调定的阈值差异会自然表现为“不合并”或“蕴含”。所以要记录 Stage2 调定后的阈值，并保存覆盖失败和训练早期的状态（VPM_idea §5.2、§6.4 已有计划）。
- 跨仿真器合并，要求各适配层的世界视图单位和坐标系一致（Stage1 记录 §3.2.9 第 1 条）；否则只在同一仿真器内合并。

## 8. 转来的检索方向，逐条核实

- **DreamCoder、Stitch、LILO、ReGAL：** 都存在，描述准确。另补了 babble、CRAFT、TroVE。
- **Silver 等的谓词发明（AAAI 2023）：** 存在。但它按文法枚举、按规划目标挑选，不按数据等价去重。更接近的是后续的 pix2pred、VisualPredicator（ICLR 2025）和 InterPreT。
- **本体对齐、实体解析：** 见本文 §3.1。
- **ARM-FM（arXiv:2510.14176，ICLR 2026）：** 存在。“跨任务复用标注函数”的说法要修正，见本文 §3.6。
- **Voyager：** 存在，本次没读正文。
- **视觉侧：** SuccessVQA、Migimatsu 与 Bohg、SORNet 已核对。开放词汇关系检测和场景图生成，本次没有核对。
- **动作 token 化：** PRISE（ICML 2024）对矢量量化后的动作编码做 BPE；Subwords as Skills（NeurIPS 2024）对离散化的动作做 BPE；FAST 存在，本次未读正文。没有找到把 BPE 类比用到条件或谓词上的工作。
