## 第二段：官方字段的用法

注意：下面第 2 处改的是 §4.4 的里程碑句子，而“里程碑的来源”还没有定（讨论记录 §4.6 第一版，§5 中的一条）。如果你认可第一版，即里程碑由适配层直接从官方判定和通用读数算出、不取自候选的谓词，那么 §4.4 这一句应改成新的来源，下面第 2 处就作废，要和里程碑一起重写。

```text
【来自 Stage1 会话（2026-10-20）：官方字段的用法已定，VPM_idea 还需改三处】

接上一段消息。Stage1 记录 §3.3 第 6 项已定（docs/Stage1/01_design_discussion.md）：谓词里一律不读环境自带的判定（ManiSkill 的 evaluate() 字段）。具体是：
- 通用函数算出的判定，如 Panda 的 is_grasping(obj)、手臂的 is_static，由适配层作为读数提供，谓词直接用；
- 要用任务特有的官方判定（如 PickCube 的 is_obj_placed），agent 照源码的公式，把它改写成以对象为参数的谓词，并声明对应哪个官方字段；第一层在本任务的状态上逐帧核对两者是否相同；
- 照官方判定改写的谓词，阈值固定为官方值，不交给内层 BO；
- 含义不合适的（如 StackPyramid 的“相邻”把叠放也算进去），仍由 agent 自己写，不声明对应；
- evaluate() 字段仍由适配层提供，只给 validator 核对和成功信号用。
理由：直接读任务特有字段的谓词，换到别的任务的状态上跑不起来，参加不了共享词表的交叉执行。

请改三处：
1. §3.5 第一层：加一项检查。照官方判定改写的谓词实例，在本任务的状态上（示范回放的各帧，加运行检查用的状态）与它声明对应的官方字段逐帧相同。
2. §4.4“固定参照”的末句：“建议人工抽查，并尽量与环境自带的判定比对”改为“建议人工抽查；能对应环境自带判定的，照公式改写并经第一层逐帧核对”。
3. §3.7“逐任务编写”：
   - 要求中补上“或任务特有的读数”，即谓词体内不写死本任务的物体名或任务特有的读数，物体只经参数进入；任务特有的几何（如孔的坐标系）要能由参数对象算出；
   - 写明官方判定的用法，即上面五条。
```
