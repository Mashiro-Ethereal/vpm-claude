# PickCube teacher 在成功轨迹上的检验（2026-10-27）

> **用途：** 检验生成的 PickCube teacher 合不合理：在真正完成任务的轨迹上，它的阶段与 Φ 是否跟得上任务的进展。这一点此前没有验证过：Stage1 不用示范（[00](00_technical_plan.md) 第 8.1 节），“链覆盖率”等检查留到 Stage2 用成功的训练 rollout 算（第 8.5 节）；而用 teacher 奖励的训练一直没有成功过（[07](07_ppo_check.md)），所以一直没算。
>
> **结论：** 在稠密奖励训出的策略的成功轨迹上，teacher 按 reach → grasp → carry → hold 推进，成功时停在最后一个阶段且 Φ = 1（确定性 100%，随机 99.95%），Φ 几乎单调上升，谓词与官方判定每一步都一致；人写的参照候选在每一步都处在同一个阶段。所以 teacher 对进展的判断没有问题，PPO 学不会不是因为它看错了进展。看到的弱点有三处，两个候选都有，属于设计层面：grasp 段 Φ 不变（最后约 3 cm 的接近与合爪没有塑形）；搬运中抓取读数闪断一步，Φ 就从 carry 段的 0.5–0.75 掉到 0.25 再回来；极少数成功时抓取读数恰好断开，teacher 停在 grasp。另发现 ManiSkill 的 GPU 环境在重置后的第一个状态上，抓取读数是旧的。

## 1. 做法【事实】

- **策略：** 第一轮 γ = 0.8、稠密奖励训出的 PPO 策略（`outputs/stage1/ppo_check/PickCube-v1-dense-seed1-20261026-202427/final_model.pt`，当时的评估成功率 99.4%）。
- **脚本：** [scripts/teacher_check.py](../../scripts/teacher_check.py)（由 Codex 按 `outputs/stage1/codex/teacher_check/brief.md` 写，单元测试 `tests/unit/test_teacher_check.py`）。
  - 环境栈同 `ppo_check.py` 的稠密那次。
  - 在 PBRS 包装的位置（ManiSkillVectorEnv 里面）换上一个只记录的观察层：生成的 teacher 与参照候选同时挂上，每步各算一次；奖励与动作都不变。
- **回合：** 两组，每组 4 次带种子的重置（10001–10004）× 1024 个并行环境，每个环境只看第一个回合，共 4096 个回合。
  - 确定性：取策略的均值。
  - 随机：从策略的高斯分布采样，torch 种子 20261027。
- **平凡成功：** 重置时方块离目标点不到 2.5 cm 的成功，与 07 第 2 节相同。下面的统计都把它剔除。
- **运行：** 1 号卡，约 50 秒。输出在 `outputs/stage1/teacher_check/20261027-002010/`：`summary.json` 是全部统计；`report.md` 是表格、逐步轨迹（含渲染出的 guidance）和 Codex 的分析；`trajectories.pt` 是逐步记录。
- **审查：**
  - 我逐行看了脚本，确认观察层的 reset、step 与 `PBRSWrapper` 一致，记录只到第一个回合结束，统计的口径与任务说明相同。
  - 重跑单元测试，190 个全部通过。
  - 用自己写的代码从 `trajectories.pt` 重算了关键数字：回合分类、链覆盖率、各类回退的次数、官方对应、grasp 段的停留步数，都与 `summary.json` 相同。

## 2. 结果【事实】

两个候选在每一步都处在同一个阶段（g 项，100%），所以下面 a–c、e、f 的数字两者相同，只有 Φ 的数值不同。

| 回合 | 确定性 | 随机 |
| --- | --- | --- |
| 成功 | 4058（99.07%） | 4031（98.41%） |
| 其中平凡成功 | 8 | 8 |
| 非平凡成功 | 4050 | 4023 |
| 失败（50 步截断） | 38 | 65 |
| 非平凡成功中从没抓住过方块的 | 0 | 0 |
| 平均回合长度 | 18.6 步 | 19.4 步 |

**a. 阶段链（非平凡成功）：**
- 成功时处在最后一个阶段且 Φ = 1：确定性 100%，随机 99.95%（4021/4023）。
- 回合中没有回退：98.07% 与 96.82%。
- 两者都满足（链覆盖率）：98.07% 与 96.82%。

**b. 回退（全部回合）。** 阶段编号变小就算一次回退；每次回退时，前一阶段的不变量确实不成立。

| 观察到的回退 | 不成立的不变量 | 确定性 | 随机 |

| hold → carry | at_goal（方块滑出目标点 2.5 cm） | 6 | 20 |

有回退的回合：非平凡成功中 78 与 128 个，失败中 36 与 64 个。

**c. 各段的时间（非平凡成功，确定性；随机组相近）：**
- 第一次进入各段的平均步数：grasp 5.4，carry 7.1，hold 17.3；成功平均在第 18.3 步。
- 平均停留步数（含第 0 步与成功那一步）：reach 5.5，grasp 1.8，carry 10.0，hold 2.0。
- grasp 一步就跳过的回合占 0.7%。
- 进入 grasp 时，TCP 离方块中心平均 4.4 cm（near 的阈值约 5.5 cm）；第一次真正抓住时平均 1.75 cm；进入 carry 时，方块离目标平均 19.3 cm。

参照候选相应为：下降步数占比 0.39% 与 0.82%，没有下降的回合 96.9% 与 91.6%，单步最大下降 0.50 与 0.55。

**e. 官方对应：** 两个候选的四条官方对应（is_grasped、is_obj_placed、is_robot_static、success），在全部记录的步上与环境的判定 100% 一致（确定性 76,150 步，随机 79,374 步）。

**f. 失败的回合：** 最后所处的阶段：
- 确定性：reach 6、grasp 11、carry 18、hold 3；
- 随机：11、17、34、3。

**g. 两个候选的差别：** 阶段在 100% 的步上相同。Φ 的差只出现在两个阶段：carry 最大 0.047（carry 的 progress 写法不同）；最后一个阶段最大 0.20（arm_static 的 scale 0.2 与 1 不同，06 第 3 节）。

**另外三个事实：**
- **成功时阶段链没走完（随机组 2 个回合，两个候选相同）。** 成功那一步，方块已在目标点、手臂已静止，但抓取读数（官方的 is_grasped 也一样）恰好变为假。carry 的不变量退回 reach；near 仍成立，同一步又进到 grasp；grasp 的守卫不成立，停在 grasp。结果是 Φ = 0.25，guidance 要求“抓住方块”，而环境判定已经成功。其中一个回合方块的中心高约 5 cm（底面离桌面约 3 cm），悬在目标点上。
- **重置后的第一个状态上，抓取读数是旧的。**
  - 确定性组 2004 个回合、随机组 2560 个回合，在第 0 步报 grasped 为真，都是爪子远离方块的时候（near 为假，TCP 离方块至少 10.6 cm）。
  - 新建环境后的第一次重置（确定性组的种子 10001）是 0 个，此后每次重置都有 625–701 个。
  - 同一种子下两组的初始位姿完全相同，抓取读数却有 2120 对不同。
- **用种子 10001 的确定性回合没有完全复现 eval.json：** 成功率 98.93%（eval.json 为 99.41%），平均长度 18.79 步（18.64 步）；1024 个环境中 889 个的回合长度相同。

## 3. 分析【推导】

1. **teacher 在成功的行为上判断正确。** 阶段按顺序推进，几乎全部成功都在最后一个阶段以 Φ = 1 结束，Φ 随步数几乎单调上升，谓词与官方判定每一步都一致。生成的 teacher 与人写的参照候选，阶段完全相同。所以 PPO 学不会，不是因为 teacher 在成功的轨迹上看错了进展。teacher 在没学会的策略的轨迹上表现如何（例如远离方块时 Φ 怎样变），这次没有检验。
2. **grasp 段没有塑形。** 从进入 grasp（约 4.4 cm）到真正抓住（约 1.75 cm），Φ 一直是 0.25：最后几厘米的接近和合爪都没有塑形信号。训练好的策略在这一段只停留约 1.8 步，但对还不会抓的策略，这正是最难碰到的一步。在 PBRS 下，在 grasp 段多停一步，奖励是 −(1 − γ)·0.25：γ = 0.8 时为 −0.05，γ = 0.99 时为 −0.0025。第一轮（γ = 0.8）的策略最多有 18% 的步处在 grasp，carry 却降到 0，与此相符。这是 01 §4.2 的设计（布尔守卫的阶段不写 progress），参照候选也一样。【假设：这是 PPO 早期学不会抓取的原因之一】
3. **抓取读数闪断时 Φ 大幅跳动。** m = 1（不去抖）时，搬运中抓取读数断开一步，teacher 就从 carry 退到 grasp，Φ 从 0.5–0.75 掉到 0.25（最大一次掉 0.48），下一步再回来。确定性组 4096 个回合里有 180 次。PBRS 下这种来回大体相消，但会给奖励加噪声。
4. **成功时阶段链没走完的情形很少（2/4023）。** 原因是 carry 的不变量要求一直抓着，而官方的成功只看方块位置和手臂静止，不要求抓着。它太少，不足以解释训练失败。
5. **重置后抓取读数是旧的，属于 ManiSkill 的 GPU 环境。**【假设：重置只设位姿，不跑物理步，接触冲量还是上一步的】
   - 影响一：PickCube 的观测含 is_grasped，所以策略看到的第一个观测受上一个回合影响。对稠密、稀疏、teacher 三种奖励都一样。
   - 影响二：teacher 在第 0 步的谓词。8192 个回合里它从没改变 teacher 的起始阶段，因为 near 都为假。
   - eval.json 是在训练结束后、同一个进程里跑的，第一次重置之前有旧的接触；这次是新进程，没有。所以复现不了 eval.json 多半是这个原因。【假设，与数据相符，没有单独检验】
6. **这次没有回答的：** 第二、三轮 PPO 为什么退回 reach、远离方块。critic 吸收势函数（07 第 6 节）仍是假设，这次没有测训练一侧的任何量。
