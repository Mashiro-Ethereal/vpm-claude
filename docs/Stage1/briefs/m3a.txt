<spec>
Reports (report.py): `Issue(code, message, where)` is reused from vpmkit.artifact. `CheckResult(name, status in {"pass","fail","warn","skipped"}, issues: list, stats: dict)`. `Layer1Report(candidate_dir, env_id, passed: bool, checks: list[CheckResult], replay_summary: dict | None, started_at, finished_at)` with `to_json()`, `from_json()`, `to_markdown()`. `passed` is True iff no check has status "fail".

Layer 1 (layer1.py): `validate_layer1(candidate_dir, env_id, *, num_envs=8, seeds=(0, 1, 2), steps=30, trajectories=None, extra_states=None, device=None) -> Layer1Report`. `extra_states` is an optional list of WorldStates (snapshots taken with this candidate's binding) that are used ONLY by check 5, to give the official check states where the environment judgment is true. Process isolation: `validate_layer1(..., isolate=True)` is the default and runs the whole validation in a fresh subprocess (e.g. `python -m vpmkit.validate.layer1 --json-out <tmp> ...` or multiprocessing with the spawn start method), returning the Layer1Report read back from JSON; trajectories and extra_states go through temporary files using tensor-dict serialisation (add `WorldState.to_dict()` / `WorldState.from_dict()` to vpmkit/world.py; no pickled classes). `isolate=False` runs in-process for callers that own a fresh process. The child disables core dumps (resource.setrlimit(RLIMIT_CORE, (0, 0))). Checks run in this order; if 1–3 fail, later checks are "skipped".
 1. "parse": stage_graph.yaml loads with yaml.safe_load; each of predicates.py, progress.py (optional), bindings.py parses with ast.parse.
 2. "schema": pydantic validation + check_graph issues (reuse the loader; collect every Issue instead of stopping at the first).
 3. "ast": check_candidate_ast issues.
 4. "run": build the env with make_env(env_id, num_envs) and a ManiSkillAdapter with the candidate's bind; for each seed: reset, Teacher.reset, snapshot + Teacher.step, then `steps` uniform random actions with snapshot + Teacher.step after each. Any exception (in bind, a predicate, a progress function, the automaton) is a "fail" issue naming the component and carrying the traceback's last lines; outputs must have shape [N] and be finite (progress_raw included). Record stats: per instance fraction true, stage occupancy, number of regressions, fraction of steps with non-empty guidance. Keep all snapshots' official entries and the teacher's instance values in memory for check 5.
 5. "official": for every entry of the graph's `official` list: conj = AND of its literals' truth (positive literal: value; negative: not value) on every state from check 4, from the trajectories and from extra_states; off = the official entry as bool. If the key is missing from evaluate(): fail. agreement = mean(conj == off). If `off` is constant over all checked states: status "warn" with code "official.uncovered" (the check cannot discriminate) — unless conj disagrees on some state, which is a fail. Otherwise agreement >= 0.995 passes, else fail. Stats: agreement, fraction true of each side, number of states, and up to 5 mismatching examples with the literals' margins.
 6. "trajectories": only when `trajectories` is given (else "skipped"). Input: list of `Trajectory(states: WorldState with T frames stacked along N, success: bool, source: str)`. Over the successful ones: every exit literal of every stage must take both truth values when all their frames are pooled (else fail, code "trajectory.constant_literal"); run Teacher.run_sequence on each; at least 90% must reach the done state without any regression (else fail, code "trajectory.pass_through"). Attach the replay summary to the report.

Replay (replay.py):
 - `Trajectory` dataclass as above; `save_trajectories(path, trajs)` / `load_trajectories(path)` using torch.save of plain tensor dicts (no pickled classes).
 - `replay_env_states(env, adapter, env_states) -> WorldState`: for a sequence of ManiSkill state dicts (as returned by env.unwrapped.get_state_dict()), set each with set_state_dict and snapshot; frames stacked along N. Works with num_envs=1.
 - `record_rollout(env, adapter, policy_fn, steps, seed) -> Trajectory` (success = evaluate()["success"] at the last frame) — a utility for tests and later Stage2 use.
 - `replay_summary(teacher, trajectories) -> dict`: per trajectory: stage transitions (frame, from, to), regressions (frame, event text), final stage, done flag; if not done: the stage it ended in, the unmet exit literals at the last frame with their margin and the predicate's threshold values, and the frame of maximum progress in that stage; within each stage segment the Spearman correlation between time and stage_progress; phi jumps at transitions; per-literal flicker count (number of truth-value toggles). Aggregate: fraction reaching each stage, median frames per stage, most frequent stuck literal. JSON-serialisable.

Layer 2 (layer2.py):
 - `ReviewBackend` protocol: `review(prompt: str, workdir: Path) -> ReviewResult(text: str, model: str | None, usage: dict | None)`; `ScriptedReviewBackend(responses: list[str])` returns them in order.
 - `build_review_prompt(task_text: str, env_source: str, candidate_dir, layer1: Layer1Report, replay_summary: dict | None) -> str`. The prompt (English) asks a reviewer to judge semantics only: does each predicate's definition match its one-sentence description; are guards necessary and sufficient for each stage transition; are invariants and regress targets sensible (after a violation, can the target stage's guard be satisfied again from the likely state? e.g. regressing to a stage whose guard needs an open gripper while the object is still held is a trap); are thresholds plausible given object sizes in the task source; do official correspondences copy the environment formula exactly; are templates accurate English. It embeds the task text, the environment source, every candidate file verbatim, the layer-1 report in Markdown and the replay summary. It demands a single JSON object: {"verdict": "pass"|"fail", "issues": [{"severity": "error"|"warning", "location": "...", "problem": "...", "suggestion": "..."}]} and says that "fail" requires at least one error.
 - `parse_review(text) -> Layer2Report(verdict, issues, raw_text, parse_ok)`: extract the first JSON object (also from a fenced block); unparseable or schema-invalid output -> parse_ok False and verdict "fail" with an error issue "review.unparseable". A "pass" verdict with error-level issues becomes "fail".
 - `run_layer2(backend, task_text, env_source, candidate_dir, layer1, replay_summary, workdir) -> Layer2Report`.
